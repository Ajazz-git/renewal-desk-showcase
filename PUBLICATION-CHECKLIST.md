# Publication checklist

## Public product showcase

- [x] Keep the application source in its separate private repository.
- [x] Use fictional sample data in the selected screenshots.
- [x] Label screenshot dates and fictional content clearly.
- [x] Avoid publishing environment values, secrets, internal implementation notes or real customer data.
- [ ] Review employment agreement and any intellectual-property, confidentiality and outside-work provisions before commercial promotion.
- [ ] Confirm that no employer code, data, documents, accounts, paid resources or proprietary material has been used.

## Hosted interactive demo

- [ ] Deploy only the dedicated demo configuration.
- [ ] Confirm that only fictional seed data is present.
- [ ] Verify reset behaviour and ensure it cannot affect a non-demo database.
- [ ] Ensure real email delivery is disabled or routed to a mail sink.
- [ ] Ensure outbound webhooks and external side effects are disabled.
- [ ] Verify demo visitor permissions and authentication boundaries.
- [ ] Check logs, environment values, private files and internal endpoints are not exposed.
- [ ] Test from an external network and on mobile.
- [ ] Add a public demo link only after these checks pass.

## Final review

- [ ] Inspect the site on desktop and mobile.
- [ ] Verify screenshot loading, text, links and metadata.
- [ ] Check the public repository from a logged-out browser.
- [ ] Update the main portfolio and resume only when the showcase is ready.
